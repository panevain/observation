# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow
[Semantic Versioning](https://semver.org/). The Prepare release workflow moves
the Unreleased entries under the new version (see CONTRIBUTING.md).

## [Unreleased]

### Added

- The coverage figures say when the map data was taken and what they leave out (#88). The status bar and the Coverage card show **OSM data as of** the date of the OpenStreetMap data (Overpass's `timestamp_osm_base`; hover for the time in UTC and when the area was built), and a line under the figures reads *Up to: trees, hedges, fences and vehicles are not counted. 'Street' includes driveways and footpaths.*, with the full list, and why the figures are "up to" but not a strict upper bound, on hover. Bundles carry the data date and a fingerprint of the area's map features (bundle format version 4, so cached bundles are rebuilt), and the demo street has a recorded data date. Scene files gain an optional `provenance` block (OSM data date, bundle build time, map-data fingerprint, app version, camera catalogue version and caveats version); older files load as before. When a restored or imported scene's area comes back with different map features, the Coverage card warns *Map data has changed since this scene was saved (saved: X, now: Y)* until dismissed. The region agent records each extract's date in its Overpass database (`update_database --version`) and sends it with every answer (`x-osm-base`), so local regions have a data date too, including ones imported before this release.
- Terrain: the 3D view follows the real lie of the land. The server samples Terrarium elevation tiles (the AWS Open Data Terrain Tiles set by default; `OBS_DEM_URL`, `off` for flat ground, and `OBS_DEM_ATTRIBUTION`) into a height grid in each bundle (bundle format version 3, so cached bundles are rebuilt), caching the tiles under `dem/` (256 MiB, kept at least 30 days). Map tiles and the coverage overlay are draped on it, buildings stand on the lowest ground under them, cameras placed on the ground stand on the terrain, and the region outline and aim marker follow it. Coverage counts the ground at the subject height above the terrain, the ground itself blocks the view behind hills, and walls start where the ground meets them. The demo street keeps working offline with two recorded elevation tiles (`mise run fixtures:demo-dem`). An area whose elevation cannot be fetched fails like an Overpass failure instead of loading flat, so a server without internet access (local regions only) needs `OBS_DEM_URL=off`. The inspector's **H** is now the height above the ground under the camera. The status bar credits the elevation data.
- Per-client rate limits on new areas and map tiles: by default each client address (IPv6 per /64) can start 10 new areas at once and then one every 6 s, and fetch 400 new tiles at once and then 10 a second. Cache hits, requests for an area already being built, and areas served by a local region or refused as busy are free. Requests over the limit get `429 Too Many Requests` with `Retry-After`, or an expired copy of the area or tile when there is one. The client waits 30 s before asking again for a tile that failed, instead of never (or, past 400 tiles, every frame). Tune with `OBS_AREA_RATE_PER_MIN`, `OBS_AREA_BURST`, `OBS_TILE_RATE_PER_MIN` and `OBS_TILE_BURST` (a rate of `0` turns a limit off). Behind a reverse proxy, set `OBS_TRUSTED_PROXIES` so clients are told apart by `X-Forwarded-For`. New metric `observation_client_rate_limited_total`.
- `mise run dev` runs a dev build of the server and client with a region agent built from this checkout (in Docker, on 127.0.0.1:8090, with its own data volume and dev tokens; `--release` for release builds). `mise run dev:regions` runs the agent alone and `mise run dev:clean` removes it. The tasks are in `mise.dev.toml`, which the committed `.miserc.toml` loads by default.
- More region controls in **Local map data**: each region shows how long ago it was downloaded, and a failed import says when it failed. Scheduled refreshes can be turned off and on per region with a checkbox, and each region can have its own interval (or go back to the server's with **Default**), 7 to 365 days (`OBS_REGIONS_MIN_REFRESH_DAYS` and `OBS_REGIONS_MAX_REFRESH_DAYS` change the range); the row says when the next refresh is due. Above the list are the region count and total disk use. The search list shows each extract's download size (asked of Geofabrik with `HEAD` and cached a day, via the new `POST /api/regions/catalog/sizes`) and marks extracts over `OBS_REGIONS_MAX_DOWNLOAD_MB` as **Too large** instead of offering **Import**. The server takes the settings at `POST /api/regions/settings` (`{"id", "auto_refresh", "refresh_days"}`, where `"refresh_days": null` returns to the default; admin token), and the agent keeps them in `regions.json`. Existing regions keep refreshing.

- An **Address** tool (**L**) in the tool rail: a card by the pointer shows the street address of the building under it (its own, never a neighbour's; off the buildings, the nearest address). Clicking selects that address, highlights every building at it and shades its group in the camera list; with the new **Settings → Click jumps to the camera list** (on by default, remembered in this browser) the list also scrolls to that group.
- Cameras are grouped by street address in the camera list, worked out from OpenStreetMap: a camera belongs to the nearest building or address point with an address within 25 m. Each group has a heading with the address and its camera count. A camera's new **Group** field overrides its address with a typed name or another nearby address (scene files gain an optional `group` per camera). Bundles carry building addresses and address nodes (bundle format version 2, so cached bundles are rebuilt), the Overpass query also asks for address nodes, and the region agent keeps them when importing (existing regions gain them at their next refresh).
- Local map data: an optional region agent (`observation-regions`, Docker target `regions`, run together with the app by the new `compose.yaml`) imports Geofabrik extracts into its own Overpass databases. Areas inside an imported region load from it instead of public Overpass, which stays the fallback elsewhere. A **Local map data** dialog (database button in the top bar) lists regions, imports new ones from a searchable list, and updates, cancels or deletes them, with live progress over server-sent events; the top bar shows a running import and a message says when it is done. Cached bundles inside a region are rebuilt after each import, and regions refresh every 7 days. Set `OBS_REGIONS_URL` and `OBS_REGIONS_TOKEN` to enable it and `OBS_ADMIN_TOKEN` to allow management from the UI; the map picker outlines regions with local data.

- Custom camera models can be edited and deleted: pick one under **Model** in the Custom model form to change its values (cameras that use it keep it and update) or delete it. A model that cameras still use cannot be deleted, and the message says how many use it. New custom models get an id no other model has, and the form goes on to edit a model once it is added. A scene holds at most 64 custom models, so adding one past the limit is refused instead of autosaving a scene that cannot be restored.
- A **Custom** detail level with a user-entered pixel density (1-2000 px/m, saved in scenes as `params.custom_ppm`) for calibrating ranges against real footage.
- Opt-in Prometheus metrics (`OBS_METRICS_BIND`), JSON logs (`OBS_LOG_FORMAT=json`) and an `x-request-id` header on every response.
- Automated releases: Prepare release runs weekly, works out the version from the `[Unreleased]` entries (or a patch release for dependency updates alone, or none when nothing shipped changed), regenerates the bundle-size treemap on the release branch and lets the release PR merge itself when green; run by hand it takes a version or makes an `X.Y.Z-dev.N` pre-release, which is tagged on top of `develop` without going through `main` (so hotfixes stay possible). Dependabot patch updates and base image digest refreshes merge themselves once their checks pass, unless labelled `hold`.
- Release images are signed with cosign (keyless).
- A `cargo-cooldown` check on pull requests: every crate version added to `Cargo.lock` or `fuzz/Cargo.lock`, indirect dependencies included, must be 7 days old (`.config/cargo-cooldown.toml`), except fixes for RustSec vulnerabilities (required in the rulesets: `mise run rulesets:apply`).
- A `hygiene (typos, unused deps)` check: typos for spelling and cargo-shear for dependencies no code uses, in both workspaces (`mise -E ci run typos`, `mise -E ci run shear`; required in the rulesets). cargo-deny gains a ban list: no OpenSSL or native-tls, reqwest only in the crates that build outbound clients through `observation-upstream`, and no crates that fetch code at build time.
- A headless-browser smoke test of the release client (`browser (wasm smoke test)`, required in the rulesets; `mise run test:browser`): the built `dist/` in the app image, loaded in Chrome with WebGL2 on SwiftShader, must start, load the demo street and start the coverage worker without errors. The wasm build is also checked against a size budget (`.config/wasm-size-budget.toml`, `mise run build:budget`).
- cargo-vet (`supply-chain/`, the `cargo-vet` check, required in the rulesets): new versions of crates that the server, the region agent or `observation-core` use need an audit, ours or an imported one (Mozilla, Google, Bytecode Alliance, Embark, ISRG, Zcash), or a recorded exemption. The 205 crate versions not covered by an import when vetting started are exempted; the client's own Bevy tree is not vetted yet.
- `image-full.yml` builds the in-image client path before release, and a `zizmor (workflow audit)` check (required in the rulesets: `mise run rulesets:apply`).
- Treemap workflow that refreshes the bundle-size chart on demand (each release regenerates it on its release branch).
- `cargo-nextest` and `cargo-llvm-cov` support (`mise run coverage`), and a zizmor audit of the workflows.
- A mode pill at the top left of the 3D view (Select, Place, Aim, Move, Region) with what a click does and the selected camera or the model being placed; the pointer changes with the tool, and the tool rail has icons.
- Search in the camera model lists.
- Per-camera colours: each type has a default colour (further cameras of a type get lighter and darker shades), and any camera's colour can be changed.
- The demo street starts with ten example cameras.
- A Region tool (R) to outline part of the area on the ground; while it is on, the coverage figures count only what lies inside. The region can be switched off, redrawn or cleared, and is saved with the scene (scene files gain an optional `region`).
- Settings menu (gear in the top bar) with a choice of UI font, Inter or Iosevka, remembered in the browser. Both are bundled (subset to Latin-1, about 100 KB together; `scripts/subset-fonts.sh` rebuilds them) and figures use tabular digits.
- Phosphor icons; each camera type has its own icon in the camera list and model picker.

### Changed

- `mise run check` also runs typos, cargo-shear and cargo-deny, so it covers every CI check that needs no Docker, browser or CI-only tool. Their tools and cargo-nextest move from `mise.ci.toml` to `mise.toml` (`mise install` now installs them), and `mise run typos`, `shear` and `deny` work without `-E ci`. `mise run test` always uses cargo-nextest.
- The Rust version is set only in `rust-toolchain.toml` (and recorded in `mise.lock`): `rust-version` is gone from the manifests, and the Docker builder's `rust` tag no longer has to match, so Dependabot moves that image tag on its own. Dependabot also bumps the fuzz nightly; the Pins workflow still bumps the root toolchain.
- Scene files are version 2: camera positions are over the terrain, with `y = 0` at the ground at the area's centre. Version 1 files and autosaves still load, and their cameras are raised onto the terrain once the area arrives, keeping their height above the ground. The coverage worker's message version is 2.
- mise 2026.7.15 or newer is required for every task, including `mise run up` and `down`: task scripts now run under bash with errexit, nounset and pipefail (`[task_config] shell`), which an older mise ignores. A mise older than CI's (2026.10.18) still only warns.
- `mise run serve --release` replaces `mise run serve:release`, which still works; `mise run rulesets:apply` asks before changing the live rulesets.

- The map picker checks areas against the size limits the server publishes in `/api/config` (which now also has `min_bbox_side_m`) instead of the client's own 20-500 m, and map tiles are fetched from its `tile_url`. The client keeps its built-in values until the server answers, and for any value that is missing or not sensible.
- The inspector is reorganised so a selected camera's settings no longer sit below the whole camera list. The coverage figures stay in view at the top, with a **Region** menu (draw, switch off, redraw or clear) and a line with the analysis settings behind them. Below them are three tabs, each scrolling on its own: **Cameras** (model, Place, the list and custom models), **Camera** (the selected camera, with previous/next arrows; it opens whenever a camera is selected) and **Analysis** (detail level, lighting, subject height and the overlay colours). A camera alone at its address shows the address under its name instead of under a heading of its own, which halves the list's height in most streets.
- The region agent's `OBS_REGIONS_REFRESH_DAYS` is now `OBS_REGIONS_DEFAULT_REFRESH_DAYS`, since regions can have their own interval. The agent refuses to start while the old name is set (unless the new one has the same value), so rename it if you set it on 0.1.0-dev.1 or dev.2.
- Coverage is computed in a Web Worker, so moving or editing a camera no longer stalls the 3D view while its visibility is worked out; the overlay and figures update when the result arrives. The worker is built by trunk alongside the app (`coverage-worker` binary, loaded from `/coverage-worker_loader.js`); if it cannot start, coverage is computed on the main thread as before. The server now caches only files whose names carry trunk's content hash for a year and has browsers revalidate everything else, such as the worker's files.
- The bundle cache is capped at `OBS_BUNDLE_CACHE_MB` (default 1024 MiB; it used to grow without bound): a bundle that would take it over the cap first deletes the least recently written bundles down to 90 % of the cap, the same batched eviction as the tile cache. Expired bundles are still kept for when the upstream is down until eviction reaches them, and a bundle larger than the cap is served without being cached. An invalid `OBS_BUNDLE_CACHE_MB` stops the server at startup. **Upgrading prunes an existing bundle cache:** at start a background task deletes the oldest bundles down to 90 % of the cap, including expired ones kept for Overpass outages; raise `OBS_BUNDLE_CACHE_MB` first to keep more. Evictions in both caches now also remove temp files of interrupted writes (over an hour old) and skip files rewritten while the eviction ran, and replacing a tile with one larger than the cap no longer empties the tile cache.
- The tile cache evicts instead of stopping at its 512 MiB cap: a tile that would take it over the cap first deletes the least recently written or revalidated tiles (oldest `.png` mtime, with their `.json` sidecars) down to 90 % of the cap, and each eviction recounts the cache from disk. A 304 revalidation now touches the tile's `.png` so tiles in use are evicted last.
- Images are based on Debian 13: distroless `cc-debian13` for the app and `debian:trixie-slim` for the region agent (the Debian 12 distroless images are no longer rebuilt). The server and region agent binaries are built with cargo-auditable, so image scanners and the SBOM see their crates.
- Rust 1.99.1 and trunk 0.22.0.
- Tooling is driven from mise. The tools only CI and the image build use (Trivy, cosign, cargo-audit, cargo-deny, zizmor, cargo-nextest, cargo-llvm-cov, cargo-fuzz, cargo-chef and cargo-auditable) are pinned in `mise.ci.toml` and locked with their checksums in `mise.ci.lock`, next to CI's environment and the security, fuzz and scan steps as tasks (`mise -E ci run <task>` runs one locally). The Dockerfile installs trunk, cargo-chef and cargo-auditable from the lockfiles, and the Pins workflow bumps the mise tools with `mise upgrade --bump`, each a week after its release. `mise run fonts` rebuilds the UI fonts with pinned fonttools and opentype-feature-freezer.
- Cameras are easier to click and tap: a press that misses every camera picks the nearest one within 14 px (22 px for a tap), unless a building hides it. Hovering uses the same reach. The Place tool still needs a direct hit, so a camera can be placed next to another.
- Docker Compose settings no longer use `.env`; `.env.example` is gone and `mise run up` starts the stack. The Compose tokens (`OBS_REGIONS_TOKEN`, `OBS_ADMIN_TOKEN`) are [fnox](https://fnox.jdx.dev) secrets declared in `fnox.toml`, with values in the gitignored `fnox.local.toml`; fnox is installed by mise for that task only. The other Compose settings (`OBS_PORT`, `OBS_LOG_FORMAT`, region limits) default in `compose.yaml` and can be overridden per run, e.g. `OBS_PORT=9090 mise run up`. `OBS_CONTACT` still comes from `mise.local.toml`, where it is now commented out by default. Move your values out of `.env`, or export them yourself before `docker compose up`.
- Upstream hosts on private networks need `OBS_ALLOW_PRIVATE_UPSTREAMS=1` (server and region agent). `OBS_ALLOW_PRIVATE_UPSTREAMS` accepts `1`/`true`/`yes`/`on` and `0`/`false`/`no`/`off`; other values stop the server at startup.
- Error messages say what went wrong and what to do next: failed area loads tell offline from a down server, a server error or damaged data; storage, import and export failures give the browser's reason (the status bar tooltip says why the autosave failed); scene, bundle, camera-model and bounding-box errors name the field and the allowed range; the server's replies name the limit (for example the size of a too-large box) and never include internal details.
- Image tags: releases publish only `devel`, `X.Y.Z` and `latest`. The old `edge`, `main`, `X.Y` and `sha-*` tags are no longer pushed and are removed by the Prune images workflow once `PRUNE_IMAGES=true`; pin deployments to a version tag.
- The CI Docker job no longer compiles the client: it builds the image around a stub `dist/` (as the Trivy scan does) and runs alongside the wasm build instead of after it, which takes the Docker build off the critical path.
- CI writes Rust and Docker layer caches from `develop` only (no longer from `main` or pull requests), keeps line tables instead of full debug info, caches trunk's wasm-bindgen and wasm-opt downloads, and no longer cancels branch runs: only a newer push to the same pull request cancels a run, so every commit on `develop`, `main`, `release/**` and `hotfix/**` is checked. Tests run under a nextest `ci` profile (`.config/nextest.toml`) that reports every failure and ends a test hung for 3 minutes. Fuzzing runs on pull requests only when the fuzzed crates or `fuzz/` change.
- `rust-toolchain.toml` is the only place that sets the Rust version for mise users; `mise run sync` checks the remaining copies.
- `OBS_OVERPASS_URL` takes up to 4 comma-separated interpreters, tried in order; malformed entries stop the server at startup. The whole-request timeout is 80 s (was 60 s) and an Overpass attempt 35 s (was 40 s).
- The Analysis section is last in the inspector.
- Scene files store a camera's colour as an optional `color` (`[r, g, b]`); the old `color_index` is ignored.
- Camera type colours are now cool and neutral (doorbell blue, floodlight green, spotlight sky blue, bullet indigo, turret teal, dome violet, indoor slate) so cones never match a step of the yellow-to-purple coverage ramp; a type gets two extra shades before they repeat. Saved per-camera colours are unchanged.
- The selection and aim markers are white over a dark casing, and the region outline is dark, so none of them reads as a camera or coverage colour.
- Flatter widget style: buttons show hover and press by fill instead of an outline, input fields have a 3:1 edge, corners are smaller (4/6/8 px) and floating cards and menus have a shadow.
- Selected camera is grouped into a name header, Position, Orientation and a collapsed Optics section; the face vector moved to the compass label's tooltip. Camera rows use an eye toggle instead of a checkbox, and the Cones and Walls toggles look different from the tools.
- The light or dark theme follows a change of the system setting without a reload: the panels, the map dialog, the 3D scene (sky, buildings, ground, camera bodies) and the coverage overlay all switch over.

### Fixed

- While the Region tool is on, the edge of the loaded area is drawn in red and the map beyond it is tinted and hatched. Corners clicked out there move to the edge, which used to look like part of the map refused corners for no reason (#71).
- Selecting a camera no longer widens the inspector: a long model name is cut short in the model list's button, and the **Group** field takes only the width its pin button leaves, which also stops the button being cut off.
- The demo street now has its 205 address nodes: the fixture had been recorded before the converter kept them, so many houses there had no address in the camera list or the Address tool.
- A scene file with two custom models of the same id, or a custom model id without the `custom-` prefix (which could replace a catalogue model), no longer leaves a model unreachable in the custom model editor: on import or restore, each such model gets a new `custom-` id and the cameras that showed it follow it. Files the app wrote are unchanged, since it has always made unique `custom-` ids. Catalogue ids may not start with `custom-`.
- Ctrl/Cmd+V pastes into text fields such as the admin token, and Ctrl/Cmd+C and X copy and cut from them. The browser's clipboard events were not wired up, and Bevy cancelled the key presses that fire them.
- Loading an area no longer fails with 502 when Overpass answers 502/503 once or does not answer in time: transient failures are retried (on the next interpreter, or once on a lone one) within the request's time budget. An interpreter that answers 429/504 rests for 30 s on its own, and a final timeout is a 504 with a clear message.
- Scrolling or clicking on the side panels no longer zooms or clicks the 3D view, and the Delete button removes the selected camera again.
- Clicks in the 3D view land under the pointer; they were offset by the tool rail and top bar.
- Large dark patches no longer flicker across the ground while zooming (the plain ground and the map tiles were fighting in the depth buffer).
- The map picker shows a stretched lower-zoom tile (or the finer tiles it has) while a tile loads, instead of an empty square.

### Security

- `mise run up` checks both released images against Release's signature and provenance for the version's tag before starting them, and runs them by the digest it checked. `mise run verify <image>` (`scripts/verify-image.sh`) does the same check on its own. The verification commands in SECURITY.md and the release notes now pin the signing identity to the release tag (`release.yml@refs/tags/v<version>`); the earlier pattern also accepted images signed by a copy of the workflow on any branch. Release publishes only on a push to `develop` or a `v*` tag, and verifies every image it publishes.
- Upstream requests (tile server, Overpass, region downloads) go through a resolver that refuses loopback, private, link-local and similar addresses, including names that resolve to them and IPv6 forms that embed an IPv4 address (NAT64, 6to4, mapped). `OBS_OVERPASS_URL`, `OBS_TILE_URL` and `OBS_REGIONS_CATALOG_URL` are also checked at startup.
- The server no longer follows redirects from the tile and Overpass upstreams, and the region agent follows them only within the original host, so an upstream cannot send them to an internal address. A 3xx from Overpass now fails over to the next interpreter and is logged with its `Location`.
- Proxy environment variables (`HTTP_PROXY`, `HTTPS_PROXY`) are ignored for upstream requests unless `OBS_ALLOW_PRIVATE_UPSTREAMS=1`, since a proxy resolves names past the filter.
- Credentials in upstream URLs are removed from startup errors.
- Bevy 0.20.1, which moves `ruzstd` to 0.9.1 and so fixes RUSTSEC-2026-0344 (a decompression bomb in its zstd decoder). The client never reached the vulnerable code, and the advisory is no longer ignored.
